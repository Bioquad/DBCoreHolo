# Contributing to Holographic DB

First off, thank you for considering contributing to Holographic DB! It's people like you that make this an amazing application.

---

## 📋 Code of Conduct

This project and everyone participating in it is governed by our Code of Conduct. By participating, you are expected to uphold this code.

---

## ❓ How Can I Contribute?

### Reporting Bugs

Before creating bug reports, please check the issue list as you might find out that you don't need to create one. When you are creating a bug report, please include as many details as possible:

- **Use a clear and descriptive title**
- **Describe the exact steps which reproduce the problem** in as many details as possible
- **Provide specific examples to demonstrate the steps** (screenshots, GIFs, etc.)
- **Describe the behavior you observed after following the steps** and point out what exactly is the problem
- **Explain which behavior you expected to see instead** and why
- **Include your environment details:**
  - Windows version (10 / 11)
  - .NET SDK version (`dotnet --version`)
  - Visual Studio version (if used)
  - Any custom configuration files and settings

### Suggesting Enhancements

Enhancement suggestions are tracked as GitHub issues. When creating an enhancement suggestion, please include:

- **Use a clear and descriptive title**
- **Provide a step-by-step description of the suggested enhancement** in as many details as possible
- **Provide specific examples to demonstrate the steps**
- **Describe the current behavior** and **the proposed new behavior**
- **Explain why this enhancement would be useful**

### Pull Requests

- Fill in the required template
- Follow the Visual Basic .NET styleguide
- End all files with a newline
- Avoid commits to the main branch directly

## 🛠️ Development Setup

### Prerequisites

- [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)
- [Visual Studio 2022](https://visualstudio.microsoft.com/downloads/) (17.8+), or any VB.NET compatible IDE
- [Git](https://git-scm.com/)

### Getting Started

1. **Fork the repository** on GitHub
2. **Clone your fork locally:**
   ```bash
   git clone https://github.com/<your-username>/DBCoreHolographic.git
   cd DBCoreHolographic
   ```

3. **Create a feature branch:**
   ```bash
   git checkout -b feature/my-feature-name
   ```

4. **Install dependencies:**
   ```bash
   dotnet restore
   ```

5. **Build and test:**
   ```bash
   dotnet build -c Debug
   dotnet run
   ```

## 🎨 Styleguide

### Visual Basic .NET Style

We follow Microsoft's Visual Basic .NET coding conventions:

- **File Scope Namespaces:** Prefer file-scoped namespaces over nested ones
- **Naming:**
  - Classes: PascalCase (e.g., `FrmDesigner`, `SphereRenderer`)
  - Methods: PascalCase (e.g., `GetProjectData`, `RenderSphere`)
  - Fields: camelCase with underscore prefix for private fields (e.g., `_viewportW`, `_containerState`)
  - Constants: UPPER_SNAKE_CASE (e.g., `MAX_ZOOM_LEVEL`)
  - Local variables: camelCase (e.g., `tableCount`, `isValid`)

- **Imports:** Place at the top of the file, grouped by System, then third-party libraries
- **Comments:** Use `'` for line comments. Keep comments brief and meaningful
- **Declarations:** Prefer explicit type declarations over `Dim` with inference when possible
- **Null Handling:** Use nullable types (`As Type?`) and null-coalescing operators

### Code Organization

- **One class per file** (exception: designer-generated code)
- **Logical grouping:** Related methods should be grouped together
- **Designer Code:** Never manually edit code generated by the Windows Forms designer in `.designer.vb` files

## 🔍 Git Workflow

### Commit Messages

Use clear and descriptive commit messages:

```
feature: Add real-time ERM validation for FK constraints

- Implement check constraint validation
- Add visual feedback (red flashing) for constraint violations
- Update tests for edge cases

Closes #123
```

Format:
- **Type:** `feature`, `fix`, `refactor`, `docs`, `style`, `test`, `chore`
- **Scope** (optional): Area of change (e.g., `renderer`, `import`, `ui`)
- **Subject:** Concise description
- **Body:** Details about the change (wrapped at 72 characters)
- **Footer:** Reference issues: `Closes #123`, `Fixes #456`

### Branching Strategy

- `main` — Stable, release-ready code
- `develop` — Integration branch for features
- `feature/*` — Individual features
- `bugfix/*` — Bug fixes
- `docs/*` — Documentation updates
